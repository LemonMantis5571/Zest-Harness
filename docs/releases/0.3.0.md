# Zest 0.3.0

Zest 0.3.0 is the first stable release following the published beta. It brings
the latest merged chat, provider, and reliability work to Windows and Linux.

## Highlights

- Chat activity is easier to follow: tool traces retain their arrival order,
  delegated workers appear under their parent chat, and background updates
  identify the chat that needs attention.
- The compact sidebar can group chats by status and shows unread completion or
  pending questions. Split-view selection and approval handling are more
  consistent.
- The model picker distinguishes API and CLI providers, supports provider
  filters, refreshes GPT, Claude, and Cursor choices, and warns when a Claude
  Code CLI is too old for a selected model.
- An optional model advisor can review a task before completion or after a
  failure, with per-request limits and isolated consent.
- Agents can create isolated interactive HTML artifacts in a conversation.
- Optional task usage traces summarize rounds, latency, usage coverage, and
  API-equivalent cost without saving prompt text, tool contents, or project
  paths. MCP tool discovery can also be enabled on demand.
- File reads can page beyond the first 256 KiB, and search covers larger files.

## Reliability and security

- Approval, notification, and split-view state handling received regression
  fixes, along with Claude CLI compatibility reporting.
- Mermaid's math-rendering dependency, `source-map-js`, `quinn-proto`, and
  `rustls` were updated to versions addressing published advisories.
- Windows and Linux release builds run the full release verification gate and
  include SHA256 checksum manifests.

## Upgrade notes

Install over an existing Zest installation. This is a `0.x` release, so keep a
backup of important workspaces before upgrading. Review approval cards before
accepting changes; approved shell commands run with your operating-system
permissions and are not sandboxed by Zest.

Official packages target Windows x64 and Linux x64. macOS and ARM packages are
not included. Installers are unsigned; checksums help detect altered or
corrupted downloads but do not establish publisher identity. Provider costs
and quota may be estimated or unavailable when an endpoint does not report
usage. Optional plugins are distributed separately.
