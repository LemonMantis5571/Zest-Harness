# Desktop feature coverage

The [feature map](../../../docs/features/README.md) is the inventory for this comparison. The Windows offline workspace scenario exercises real GPUI controls and a local provider. Tauri's browser suite exercises the React UI with its fixture backend. A shared Rust implementation alone does not establish equivalent controls, provider integration or accessibility.

| Work a user can do | Evidence in GPUI | What a switch would change |
| --- | --- | --- |
| [Chat and queue follow-ups](../../../docs/features/chat-turns-and-streaming.md), [answer questions or plan](../../../docs/features/questions-and-planning.md), [approve tools](../../../docs/features/tool-approvals.md), [ask side questions](../../../docs/features/btw-side-questions.md) | The native scenario sends two prompts, persists the queue and history, denies and approves a write, answers a question and runs a side conversation. | The core chat loop is available. Timing a remote model response would also measure the provider and network. |
| [Attach files](../../../docs/features/attachments.md), [read project files](../../../docs/features/project-file-tools.md), [run shell jobs](../../../docs/features/shell-commands-and-jobs.md) | The scenario opens a file, sends an attachment into the agent's restored context and opens the jobs panel. | Both use shared Rust tools. File selection, paste and presentation are frontend work. |
| [History and recovery](../../../docs/features/threads-and-history.md), [splits](../../../docs/features/split-workspace.md), [command palette](../../../docs/features/command-palette-and-shortcuts.md) | The scenario reopens and forks a chat, finds saved text and opens a second chat in a split. Native Ctrl+K searches chats and panels. | Tauri also has nested, resizable panes and configurable shortcuts. The common thread store and index are timed separately. |
| [Branch changes](../../../docs/features/workspace-changes-and-review.md), [worktree chats](../../../docs/features/worktree-chats.md), [linked pull requests](../../../docs/features/pull-requests.md) | The scenario compares changes before and after a commit and after reopening the chat. GPUI opens a project or existing checkout. | Tauri creates and manages isolated chat worktrees and opens pull request details, checks and log links. A native Changes panel covers only part of that workflow. |
| [Delegation cards](../../../docs/features/delegation.md), [coordinator](../../../docs/features/delegation-coordinator.md), [workbench panel](../../../docs/features/workbench-panel.md) | The native board drives a real worker, reviewer and patch application in an offline Git project. It also exposes files, checkpoints and jobs. | The coordinator is shared. Its Rust test times would measure the same implementation. The two workbenches have different navigation and review controls. |
| [Model and effort](../../../docs/features/model-and-effort-selection.md), [sign-in](../../../docs/features/providers-and-sign-in.md), [native providers](../../../docs/features/provider-runtime.md), [CLI providers](../../../docs/features/cli-agent-providers.md), [advisor](../../../docs/features/advisor.md) | GPUI reads the shared provider configuration, exposes model, effort and permission selection, and implements supported login flows. | Live sign-in, remote provider latency, advisor configuration and every external CLI/provider combination were outside the offline run. |
| [Context](../../../docs/features/context-budget.md), [usage and quota](../../../docs/features/usage-and-quota.md), [skills and commands](../../../docs/features/skills-and-slash-commands.md), [MCP](../../../docs/features/mcp-servers.md) | Native panels expose usage, compaction, skills and MCP commands. The scenario reads saved usage and opens relevant panels. | Tauri has additional configuration screens. Provider quota refresh and remote MCP server latency depend on external services. |
| [Message rendering](../../../docs/features/message-rendering.md), [interactive HTML](../../../docs/features/html-artifacts.md), [browser and web search](../../../docs/features/browser-and-web.md) | GPUI renders Markdown, code and tool traces. Renderer trials cover text, lists, tables and fenced code using the same content. | Tauri ships the agent browser and interactive HTML viewer. GPUI's experimental embedded webview does not implement either workflow. Native diagram and rich-content parity remains incomplete. |
| [Settings and profile](../../../docs/features/settings-and-appearance.md), [plugins](../../../docs/features/plugins.md), [notifications](../../../docs/features/notifications.md) | The native settings panel exposes model and permission controls. | Plugin management and the full Tauri appearance/profile UI would be lost. Parity for background OS notifications was not demonstrated. |
| [Desktop shell](../../../docs/features/app-shell.md), [GPUI workspace](../../../docs/features/gpui-workspace.md), [verification and release](../../../docs/features/developer-verification-and-release.md) | GPUI builds and runs from source on Windows. Windows CI exercises the offline native workspace. | Tauri supplies the Windows and Linux release installers. Windows accessibility results are in the comparison. End-user screen reader, real CJK IME, mixed-DPI and Linux native-workspace validation remain open. |
| [Offline fixtures](../../../docs/features/offline-fixture-mode.md), [UI control CLI](../../../docs/features/ui-control-cli.md) | GPUI has an offline native demo, a window scenario and a GPUI test-context scenario. | The existing UI control CLI and Playwright fixture cover the web UI. They would need native equivalents for the same automation coverage. |
| [Terminal client](../../../docs/features/terminal-cli.md), [headless daemon](../../../docs/features/zest-serve.md) | Both are independent of the desktop renderer. | Switching the desktop frontend would leave the CLI and daemon using the same Rust code. |

The native scenario and deployed packaging targets can be inspected in the [workspace check](../src/workspace_test.rs), [board check](../src/workspace/board/selftest.rs), [Windows GPUI workflow](../../../.github/workflows/gpui-windows.yml) and [release workflow](../../../.github/workflows/release.yml).
